# 作業計画（Hack Day 2日間・3〜5人）

仕様は [spec.md](spec.md)、会話履歴とスマホアプリの要件は [history.md](history.md) を参照する。時刻は開始からの経過時間（H+n）で書く。実際のスケジュールに合わせて読み替える。PC は使わない。

## 1. 着手前にやること

| 項目 | 担当 | 完了条件 |
|---|---|---|
| 買い出し（[spec.md 9章](spec.md#9-部品表bom)） | 全員 | I2S アンプモジュール、5V の USB AC アダプターと分岐基板、ゴム・スポンジが手元にある |
| VS-SGE20LA の準備 | P2 | 親機を充電し、玄関子機に電池を入れ、呼出音を音1・音量大にし、音声応答を切ってある |
| ModusToolbox の準備 | P1, P2, P3 | `firmware/psoc6` をビルドして基板に書き込める |
| 中継の仕様の相談（[spec.md 5.4](spec.md#54-会話サーバーの中継)） | P4 | 会話サーバーの担当者と、受け口の形と担当が決まっている |

| 定型音声の生成（[spec.md 5.7](spec.md#57-定型音声)） | P4 | U01 と X01 の WAV が door_neutral の声でそろっている |

## 2. 役割分担

### 5人の場合

| ID | 担当 | 主な成果物 |
|---|---|---|
| P1 | PSoC 6 の音 | チャイムの登録と精度の測定、マイクの音の送信、I2S アンプでの再生、定型音声 |
| P2 | 押下と機構 | SG90 2つの PWM 制御、5V の配線、押下アーム、ブラケット、ガード板、スピーカーの箱 |
| P3 | PSoC 6 の通信と状態遷移 | 中継との WebSocket、Edge Function との通信、状態遷移、送信待ちと再送 |
| P4 | 会話サーバー | FastAPI の中継（LiveKit への参加）、`house_rules`、会話の試験（T5、T6） |
| P5 | アプリと Supabase | テーブルと RLS、本体用の Edge Function、React Native のアプリ、プッシュ通知 |

デモ台本、スライド、README、動画は Day 2 の後半に全員で分担する。

### 3〜4人の場合

- 3人: P1 と P2、P4 と P5 をそれぞれ1人が兼ねる。アプリは来客の一覧・詳細とモード切替だけにする。
- 4人: P4 と P5 を1人が兼ねる。

## 5. リスクと対策

最初の3時間で R1〜R3 と R8 を判定し、ダメなら代替案に切り替える。

| ID | リスク | 影響 | 対策 | 代替案 |
|---|---|---|---|---|
| R1 | PSoC 6 のマイクで訪問者の声がうまく拾えず、文字起こしが崩れる | 会話不能 | マイクを親機スピーカーに寄せる。親機の受話音量を上げる | 外付けのマイクモジュールを PSoC 6 につなぐ |
| R2 | PSoC 6 で、TLS の WebSocket、音声の送受信、I2S の再生を同時にこなせない | 会話が途切れる | 16 kHz・モノラルにし、バッファを小さく保つ。Day 1 の前半に負荷を測る | 送る音を 8 kHz に下げる |
| R3 | 会場から会話サーバーまでが遅い、または labpc が止まる | 会話不能 | 会場で応答時間を測る。iPhone のテザリングを用意する（接続は確認済み）。担当者と停止時の連絡方法を決める | 定型音声だけで応答する |
| R4 | LLM が不在や住人の情報を話す | 安全上の問題 | `house_rules` と意地の悪い発話の試験 | 該当する返答を出した場合は、`house_rules` を直すまで外出モードを使わない |
| R5 | 本体の声の回り込みで、エージェントが返答を途中で止める | 会話が途切れる | 再生中はマイクの音を送らない | 中継側でもエージェントの発話中は PSoC 6 の音を流さない |
| R6 | チャイムの取り逃し、またはテレビや会話での誤検知 | 応答しない、または無人の玄関に応答する | 実際の呼出音で登録し直す。しきい値を調整する | 手動の合図を用意し、使った場合は発表でその旨を明言する |
| R7 | ModusToolbox の環境構築に手間取る | PSoC 6 側の遅延 | 事前にビルドと書き込みを済ませる | 動く環境を持つメンバーの PC でビルドする |
| R8 | I2S アンプが手に入らない | 声が出ない | 1 日目の前に買う | アナログ入力のアンプモジュールと PSoC 6 の PWM 出力で代える |
| R9 | SG90 の電流で電源が下がり、PSoC 6 がリセットする | 押下の途中で止まる | SG90 は外部の 5V から取り、2つを同時に動かさない。電解コンデンサを付ける | SG90 の電源を PSoC 6 と別のアダプターに分ける |
| R10 | 親機の自動切替で本体の声が途切れる、または玄関子機と近すぎてハウリングする | 会話が乱れる | スピーカーの音量とマイク穴との距離を調整する。デモでは玄関子機を離して置く | プレストークを使う（[spec.md 3.7](spec.md#37-ハンズフリー親機は半二重として扱う)） |
| R11 | アプリと Supabase の作業が膨らみ、本体の結合が遅れる | 全体の遅れ | 来客の保存と一覧・詳細、モード切替を先に終える | 削除などを後回しにする |
| R12 | RLS の誤りで他の家の記録が読める | プライバシーの問題 | 全テーブルで RLS を有効にし、history.md 8章の試験を通す | 試験が通るまでアプリを公開しない |
| R13 | 通常モードで住人が先に出たのに本体が【通話】を押し、通話を乱す | 住人の通話が切れる | 通常モードの動きを決める（[spec.md 10章](spec.md#10-未確定事項)） | デモはおまかせと外出のモードで行う |

## 6. デモ構成

- 机の上に VS-MGE20（充電台に立てる）を置き、本体を取り付ける。玄関子機 VS-VG562 はハウリングしないよう離れた場所に置く。
- 1本目（おまかせモード）: 配達員役が子機を押し「ヤマト運輸です、お荷物のお届けです」と話す。本体が置き配を頼んで終話し、スマホに通知が届く。アプリで会話の全文と対応結果を見せる。
- 2本目（同じモード）: 配達員役が「クール便なので置けないんです」と断り、本体が不在票を頼む。
- 3本目（外出モード、アプリで切り替える）: 訪問者役が「〇〇さん、今お留守ですか」と聞き、本体が不在を明かさずに応じる。
- 4本目: Wi-Fi を切った状態でチャイムを鳴らし、定型音声で応答して終話し、回線が戻ってから記録がアプリに出ることを見せる。
- 発表では、PC を使わず PSoC 6 1枚で動くことと、不在時に置き配を頼まない理由（[spec.md 3.5](spec.md#35-置き配を頼むのは在宅時に限る)）を説明する。

## 7. リポジトリ構成

```
README.md              JPHacks の製品説明
LICENSE
docs/                  仕様書、作業計画、会話履歴の要件
firmware/
  psoc6/               PSoC 6 の本体ファーム（チャイムの登録・検知、Wi-Fi、これから会話と押下）
  wifi-check/          PSoC 6 の Wi-Fi 接続テスト（Infineon のサンプルが元）
tools/
  serial-monitor/      wifi-check のシリアル出力を見る監視画面
backend/
  voice-agent/         会話サーバー（FastAPI と LiveKit の会話エージェント。これから中継を足す）
supabase/              テーブル、RLS、Edge Function（別セッションで作成中）
app/                   React Native のスマホアプリ（これから）
```

- ModusToolbox の共有ライブラリ（mtb_shared）は `firmware/mtb_shared` に作られる。リポジトリ直下の `.gitignore` で除外している。
- Infineon のサンプル由来のライセンス（`LICENSE`、`LICENSE.repository`）は、それぞれのファームのディレクトリに置いている。
