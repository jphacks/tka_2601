# 本体ペアリングの実装・検証

対象はIssue #31。main 419bf5fを基準に、設定画面からペアリングコードを入力し、実際に登録された本体を読み直して表示する経路を追加した。

## 実装したこと

設定に本体の登録・確認への導線を追加した。登録画面は8文字のコードを検証し、空白・ハイフン・小文字を受け付ける。未認証の画面は既存のルートガードで保護する。

保存には既存のclaim_device RPCを使う。RPCの成功後に返された本体IDと、実際に取得した本体IDを照合する。保存後の読込に失敗した場合、消費済みコードを再送せず結果の取得だけを再試行できる。登録済みはWi-Fi接続済みや設定反映済みを意味しない。通信には10秒の上限を設けた。登録結果が不明な場合は、本体の読戻しを行うまで登録RPCを再送させない。応答待ちの解除とリクエスト取消も単体試験で確認した。

既存アプリは1店舗1台を表示するため、claim_deviceに店舗単位のトランザクションロックと登録済み確認を追加した。2台目と同時登録の敗者にはPT409を返し、未使用コードを保持する。既存の本体やデータを削除・移動する変更ではない。

## 実行した検証

| 検証 | 結果 |

| 他店舗への上書き、直接の所有権変更 | 拒否を確認 |
| モバイルのロジック試験 | 59件成功 |
| 型検査 | 成功 |
| 変更ファイルのlint | 成功 |
| Webの実画面 | 設定から登録画面へ遷移、不完全入力の送信抑止、無効コードの拒否、小文字・ハイフン付きコードでの登録、再読込後の本体表示を確認 |
| スマホ幅 | Webの390×844で長い本体名・店舗名と操作ボタンを確認 |

稼働済みのローカルSupabase tka_2601を再利用した。DBのリセット、新規スタックの作成、本番への適用は行っていない。共有DBには今回のRPCだけを限定適用した。

アプリにはESLint設定がなかったため、Expo SDK58の設定と開発依存を追加した。既存ランタイム依存の版は変えていない。全体lintには、変更していないauth.tsxとbadges.tsxの既存set-state-in-effect違反2件、既存警告4件が残る。今回変更したファイルのlintは成功している。

## 未確認と範囲外

iOS・Androidの実機操作、本番Supabase、Vercelへの配備、XIAOのWi-Fi設定、物理プッシャーの動作は未確認。コードは既存の管理者用register_deviceで発行する。再発行・有効期限・解除・交換は今回実装していない。

既存claim_deviceの呼び出し経路から本体の所有権と保存結果を確認した。単体試験の代替実装を本番の保存成功として扱っていない。

## 再現

既存ローカルスタックが稼働している状態で、リポジトリ直下から実行する。

```sh
deno run --cached-only --allow-env --allow-run --allow-net=127.0.0.1:56421 supabase/tests/device_claim_http_local.ts
cd mobile
npm run typecheck
npm test
npm run lint
```

HTTP試験はローカルの固定接続先を検査し、一意の試験用データだけを作成・削除する。鍵をログへ出力しない。全体lintの既存指摘は上記のとおり。
