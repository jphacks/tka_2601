# XIAOの通話上限・再検知抑止

対象はIssue #45のうち、既定50秒の通話上限と終話処理後20秒の再検知抑止。main 419bf5fを基準にした独立差分であり、進行中の単一プッシャー対応と統合が必要。

既定の通話上限を600秒から50秒へ変更した。セッション、READY待ち、押下完了待ちにも経過時間の判定を加えた。ボタン操作を試みた通話の終了処理後は、成功・失敗を問わず20秒間、新しい自動・手動の通話要求を捨てる。確認待ちの復旧ロックは、クールダウンの満了や停止操作で解除しない。

## 検証

ホスト試験のC/C++15スイートとPython・UI試験は成功した。既存の設定ツール試験3件はpython-dotenvがないためスキップ。50秒・20秒の境界、時計の周回、待機期限、失敗経路、保留されたチャイムの抑止、開始押下前の取消、終了未確認状態を検証した。

## 未完了

通信の同期処理がブロックする間は、50秒の判定を直ちに実行できない。厳密な時間内の終話を保証するには、通信処理へ残り時間を渡す変更と実機検証が必要。

ユーザーの写真ではPanasonic製親機の通話／終話が同じボタンであることを確認した。正面の写真から型番は特定できていない。VS-MGE20用の呼出15秒・保持500msを、この親機の確定仕様として適用していない。この2点と機種別プロファイルは未完了であり、Issue #45を閉じない。

PR #29と単一プッシャー対応の復旧処理は別作業で進行中。統合時には、その確認待ち・自動復旧の条件を維持する。ホスト試験の成功を実機での通話成立・終話確認には用いない。
