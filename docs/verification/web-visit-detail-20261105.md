# Web来客詳細の表示検証

対象はIssue #32。最新版のWeb用「来客詳細（宅配） (2).png」に合わせ、概要を左、会話を右へ配置した。

本文の実幅が800px以上の場合だけ2列にする。Web来客詳細の本文上限を1040pxとし、他画面の720px上限を保つ。狭い画面とネイティブは縦配置のまま。空の会話はその旨を表示し、来客IDが変わる場合は内部画面を作り直して古い取得結果を捨てる。

## 確認結果

実ローカルDBに保存した来客・会話を使い、1440×1000のWebで2列表示、390×844で縦表示を確認した。長文6件の会話が折り返され、両幅でページの横はみ出しがないことを確認した。

1440px幅で概要内の宅配表示はx=358、会話見出しはx=715.1だった。390px幅では概要の下に会話が並んだ。実レコードを読み込む画面で確認しており、疑似APIの応答による表示確認ではない。

型検査と変更ファイルのlint、既存モバイル試験は成功。削除確認の操作中にアプリ内ブラウザーの操作が応答しなくなったため、削除の実行・取消と空会話・取得失敗の実画面確認は完了扱いにしない。ネイティブ実機と本番配備も未確認。

参照画像を基にした配置変更の実装と、現在確認できた状態を記録した。Issue #32は未マージ・追加確認待ちとして扱う。
