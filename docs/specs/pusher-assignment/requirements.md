# プッシャー個数・機能割り当ての要件案

2026年11月4日作成。実装・検証状況は[検証記録](../../verification/pusher-assignment.md)を参照。

## 目的と範囲

スマホアプリから、通話開始・終話に使用するプッシャーを1個または2個選び、機能を割り当てる。通話開始と終話が同じ物理ボタンの親機では、同じプッシャーを開始時と終了時に1回ずつ動かす。

対象はXIAO単独ファームウェアとする。今後はXIAO＋自作基板を採用し、基板の到着まではXIAOと購入済みのアンプ等で実装を進める。E84＋M5は初期試作として扱い、今回および今後の実装対象から外す。この構成方針はユーザーの明示指示による。

ユーザーから確認できた希望は、アプリで個数・機能を設定し、ファームウェアへ送ること。以下の通信経路、反映手順、例外時の動作は設計上の提案であり、実装済み・実機確認済みを意味しない。設計は[design.md](design.md)、実装単位と検証は[tasks.md](tasks.md)に記載する。

個数は「使用する個数」とし、接続数の自動検出は行わない。現在のファームウェアには接続を読み取る処理がなく、PWM出力の成功だけではサーボの接続を確認できない。角度・押下時間の調整には既存のUSB調整画面を使う。アプリからの角度調整や遠隔押下テストは今回の範囲に含めない。XIAOの3番出力は既存の解錠用USBテスト・調整として保持し、今回の通話用1個・2個設定に含めない。

## 要件と受け入れ条件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| PA-01 | アプリで使用する個数と機能を設定する | 1個ではプッシャー1・2のいずれかを選び、開始・終話を同じ1個に割り当てる。2個では開始・終話を別々に割り当て、入れ替えられる。未割り当てや使用個数との矛盾は保存できない。 |
| PA-02 | 物理プッシャー単位の調整値で動かす | 1個構成の開始・終話は、同じGPIO・待機角度・押下角度・押下時間・復帰時間を使う。未使用出力にはPWMを出さない。通話前待機だけは開始操作に適用する。 |
| PA-03 | アプリの設定を本体単位で保存する | 所属グループの対象本体だけを変更できる。個数と割り当ては一括保存する。同時編集で先に保存された変更を、古い画面から無条件に上書きしない。 |
| PA-04 | 押下前に設定を本体へ届ける | 通話セッション外でXIAOが取得する。XIAOが検証・永続保存・読み戻し・有効化を終えてから適用完了を報告する。設定通信だけではサーボもスピーカーも動かさない。 |
| PA-05 | 進行中の操作を同じ設定で完了する | 通話・押下・復帰・テスト・調整・切断後処理の実行中は設定を切り替えない。通話途中に変更されても、終話まで開始時の割り当てを使う。 |
| PA-06 | 保存と本体反映を区別して表示する | アプリで読込中、本体未登録、保存失敗、反映待ち、反映済み、反映失敗、未対応ファームウェアを区別する。本体の通信時刻だけで反映済みと判断しない。 |
| PA-07 | 再送・オフライン・再起動で誤適用しない | 同じ版・同じ内容の再送で押下や再保存を繰り返さない。古い版、同じ版の別内容、非対応の割り当てを拒否する。反映失敗時は直前の正常設定を維持する。再起動だけでは押下しない。 |
| PA-08 | 共有ボタンで不確かな押下を重ねない | 押下前の取消では動かさない。共有プッシャーの開始操作が途中で中断・失敗した場合、自動で終話用の2回目を押さず、要確認状態を表示する。電源断・再起動でも要確認を解除しない。正常な開始・復帰が完了した場合だけ、通常の終話または切断後の終話を1回行う。 |
| PA-09 | 既存設定を保持して移行する | XIAOの既存2個構成の配線・調整値と、3番の解錠用調整値を保持する。アプリの初期表示だけで既存設定を上書きしない。未対応ファームウェアへ反映済みと表示しない。 |

## 実機で確認する前提

共有対象のボタンが、待機・呼出中には通話開始、通話中には終話として働くことを対象の親機で確認する。ボタンの名称だけで対応機種と判断しない。

現在は親機の通話状態を検知していない。PWM動作完了は実際の通話開始・終話の証明にはならず、手動操作や親機の自動終了後に押すと、意図と逆の操作になる可能性がある。対象機種の押下時間、復帰時間、通話上限、手動操作時の動作を実機検証し、自動運用の可否を判断する。この確認が済むまでは1個構成の実機対応完了とは扱わない。
