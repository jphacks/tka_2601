# M5Stack BasicとPSOC Edge E84のWi-Fi通信

E84から届く音声を順次再生し、通話・終了ボタン用サーボを動かすM5Stack Basic用Arduinoファームウェアです。従来のUDP ping/chime表示も残しているため、音声入力なしでWi-Fi通信だけを確認できます。API接続と録音はE84が担当します。

## 設定と書き込み

まずE84で接続できているWi-Fi設定から、M5の設定を作成します。Pythonの追加パッケージは不要です。

```sh
cd /Users/fukawanozomi/Documents/ChatGPT/jphacks/PSOC_Edge_E84
python3 configure_m5.py --prepare-receiver
```

このディレクトリに `link_config.h` が生成されます。SSID・パスワードと、E84と共有するランダムなトークンを含みます。Git対象外で、コマンドの出力には資格情報を表示しません。M5へAPIキーを設定する必要はありません。

M5Stack BasicをUSB接続し、Arduino IDEなどでポート名を確認します。次の `/dev/cu.usbserial-...` を実際のM5のポート名に置き換えてください。

```sh
cd /Users/fukawanozomi/Documents/ChatGPT/jphacks/M5Stack_Basic_E84_Link
bash run.sh build
bash run.sh upload /dev/cu.usbserial-...
```

`upload` はビルドも行います。書き込むとM5の既存プログラムが置き換わります。このMacのArduino IDE付属CLI、ボード **M5Core**（`m5stack:esp32:m5stack_core`）、M5Unified/M5GFXを使います。Arduino IDEで同名の `.ino` を開いて書き込むこともできます。設定ヘッダーを初めて作成した場合も反映されるよう、`run.sh` はクリーンビルドします。

M5画面で `Wi-Fi: Connected`、`IP: ...`、`UDP: 8768 Ready`、`TCP: 8769 Ready` を確認します。TCPポートは設定したUDPポート+1です（UDPは1024〜65534）。表示されたIPをE84へ設定します。以下の `172.20.10.4` は例です。

```sh
cd /Users/fukawanozomi/Documents/ChatGPT/jphacks/PSOC_Edge_E84
python3 configure_m5.py --host 172.20.10.4
make -j8 program
```

共有トークンは最初に作成した値を引き継ぎます。IPだけの変更ならM5の再書き込みは不要です。UDPポート・トークン・Wi-Fi設定を変更した場合は、両方へ再書き込みします。詳細は [E84側の設定手順](../PSOC_Edge_E84/docs/m5-link.md) を参照してください。

## 通信確認

E84がWi-Fiへ接続した後、E84のUART画面で `t` を押します。Enterは不要です。次のログが出ればE84からM5への送信と返信の両方を確認できています。

```text
[M5] PONG received. E84 <-> M5Stack Wi-Fi communication OK.
```

M5画面の `Ping` が増えて `Ping received / Pong sent` と表示されます。`Chime` はチャイム通知の受信回数です。重複したIDは受信回数へ追加せず、pingの再試行には返信します。UDPのping/chimeだけでは音声やサーボは動かしません。

M5のAボタン、またはM5の115200 baudシリアルで `s` / `h` を押すと接続状態を表示します。通信が切れた場合は自動再接続し、IP変更時にはUDPの待ち受けを再開します。M5のIPが変わったらE84側の `--host` を設定し直してください。

iPhoneではE84と同じインターネット共有へ接続し、「互換性を優先」を有効にします。端末間通信が制限されたネットワークでは応答が届かないため、その場合は端末間通信を許可した2.4 GHzルーターで確認します。

## 音声ストリーミング

### Webスライダーで角度・秒数を調整して保存する

対応版をM5へ書き込んだ後、Arduinoのシリアルモニターを閉じて次を実行します。

```sh
python3 calibration_ui/server.py --serial-port /dev/cu.usbserial-58650035241
```

[角度調整画面](http://127.0.0.1:8767/)の「調整開始」を押し、通話用・終了用それぞれの待機位置と押す位置をスライダーで合わせ、「本体に保存」を押します。数値入力も可能です。角度は反転を適用した後の物理PWM指示値（0〜180°、1000〜2000µs）です。実角度をセンサーで測定しているわけではありません。初期値は通話が待機180°／押下0°、終了が待機180°／押下150°です。

通話ボタンを押すまでの待ち時間（0〜30秒）、通話・終了それぞれの押下時間（0.1〜2秒）、待機位置へ戻す時間（0.1〜3秒）もスライダーで設定できます。初期値は待機3秒・押下0.3秒・復帰1秒です。秒数を変えるだけではサーボは動きません。「本体に保存」で角度と秒数を一緒に保存します。旧版の保存済み角度は引き継ぎます。

「通信診断」の「UDP疎通を確認」で、ボタンを動かさず認証済みの往復応答を確認できます。「E84 ↔ M5」の表示には確認中・確認済み・応答なしと最終成功時刻を表示します。成功から60秒以上経過した結果は「要再確認」とし、Wi-Fi接続表示やM5が応答を送信したログだけでは確認済みにしません。`[E84↔M5]` の日本語ログには、疎通結果・M5でのチャイム受信・音声用TCPの認証も記録します。

同じ画面の「E84 ライブログ」には、E84とM5のUSBシリアルから読み取った実ログを1秒間隔で表示します。M5の押下・復帰・PWM停止も表示します。検知、サーバー接続、M5再生、聞き取り、返答待ちを日本語の状態表示でも確認できます。認識した来訪者の発話、AIの返答、agentの状態、既知のサーバー終了理由も表示します。E84は `/dev/cu.usbmodem*` を自動検出し、必要なら `--e84-port /dev/cu.usbmodem1103` で固定します。E84を別のシリアルモニターで同時に開かないでください。

画面の「状態確認」「チャイム検知を再待機」「通話を終了」はそれぞれE84の `s` / `e` / `q` を送ります。画面を開くだけでは通話を開始しません。実チャイムの開始確認を手動開始で置き換えないよう、この画面から `c` は送れません。ログはRAMに直近500行だけ保持し、USBが外れた場合は再接続を待ちます。

「通信診断」には、次の経路ごとに独立したボタンがあります。E84側も確認する場合は `--e84-port` を指定して起動します。

| 診断 | 確認内容 |
|---|---|
| Mac ↔ M5（USB） | 本体設定の読み戻し |
| Mac ↔ E84（USB） | 今回の診断コマンドへの応答 |
| M5のWi-Fi接続 | AP接続・IP・ゲートウェイ・電波強度 |
| E84のWi-Fi接続 | AP接続・IP・ゲートウェイ・電波強度 |
| E84 ↔ M5（UDP） | 認証済みPING/PONGの往復 |
| E84 ↔ M5（音声用TCP） | HELLO/READY認証とPING/PONG |
| E84 ↔ API（HTTPS） | 証明書検証・API認証・`/api/status`の応答 |
| E84 ↔ API（WebSocket） | 音声用接続のTLS・API認証・READY・PING/PONG |

各結果に確認時刻・所要時間・失敗理由を表示します。成功から60秒で「要再確認」に変わり、自動で再診断はしません。Wi-FiのAP接続と、無線経由での往復成功は別に表示します。M5からAPIへ直接接続する経路はありません。APIはE84から確認します。WebSocket診断は未ペアリングの診断用キーを使い、会話・録音・音声再生・ボタン操作を開始しません。診断は同時に1つで、通話中はUDP・TCP・API診断を受け付けません。調整中などM5が音声用接続を拒否した場合も結果に表示します。USBを外した場合は再接続を待ち、片方のUSBが未接続でも他方の診断は使えます。

保存先はM5のNVSで、電源を切っても保持します。次回以降のUSB `1` / `2` テスト、E84からの通話開始・終了、切断時の終了操作が同じ保存値を使います。保存済み設定があればコンパイル時の初期値より優先します。各サーボの待機位置を別々に保存できます。

画面を開くだけ、または「調整開始」だけでは動きません。押す位置のプレビューは設定した押下時間、待機位置のプレビューは1.5秒で復帰を開始し、設定した復帰時間の後にPWMを停止します。サーボを切り替えるときも前のサーボを先に戻します。「変更を取り消す」、または2分間無操作で未保存の変更を破棄します。調整中は新しい通話を受け付けず、通話中は調整開始を拒否します。

Web UIの「通話ボタンを1回押す」「終了ボタンを1回押す」は、現在の角度・秒数で押下と復帰をテストします。未保存の調整値でも試せます。テストだけで保存やagentの起動は行いません。動作中は二重テスト・設定変更・新規通話を拒否し、「テストを中止して戻す」で待機位置へ戻します。USBの旧 `1` / `2` は引き続き調整中には拒否します。

終了側の取り付け方向が通話側と逆の場合は、調整中に「終了側の向きを反転」を使います。終了側の待機・押下の両方を `180 - 現在の角度` に変換し、通話側と秒数は変えません。例えば180°→163°は0°→17°になります。反転操作だけではPWMを出さず、NVSへも保存しません。ご自身で位置を確認して「本体に保存」すると、通常通話・単体テスト・再起動後も反転済みの同じ角度を使います。再起動時にもう一度反転することはありません。反転を再度押すと元の編集中角度へ戻ります。

「本体に保存されている設定」に、NVSから読み戻した待機角度・押す角度・時間と、現在使用している設定（本体保存値／編集中／初期設定）を表示します。保存時もNVSの読み戻しが一致したことを確認してから成功を返します。起動ログの角度もコンパイル時の初期値ではなく、実際の使用値を出します。

1回の押下では、開始時の角度・時間を固定して「押す位置への指令を1回 → 指定時間その角度を保持 → 待機位置への指令を1回 → 復帰時間後にPWM停止」の順に動きます。途中で別の角度への追い押しを行わず、保存・取消・切断が重なっても同じ復帰を再実行・延長しません。角度スライダーは指を離した時点で1回プレビューし、前の押下・復帰が終わるまで次の角度を適用しません。 プレビュー動作中は単発テストを無効にし、拒否されたテストを後から自動再試行しません。PWMはLCDから独立した低速LEDCタイマーで毎回duty=0から開始し、復帰後は `ledc_stop` とGPIOのLOW固定で信号を停止します。前のサーボのパルス幅を次の接続へ引き継ぎません。PWM更新はフェードサービスに依存しない `ledc_set_duty` / `ledc_update_duty` を使います。プレビュー完了は通話終了とは分けて記録します。 ログの `at_ms` は本体のミリ秒時刻、`source=saved` は本体保存値を使った動作です。SG90の実角度や接触力を測定する機能はありません。

USB状態応答で制御ループを待たせないよう、起動時にUART送信バッファを2048バイト確保し、サーボ待機・押下・復帰中はLCDを再描画しません。押下時間は制御ループで判定するためミリ秒単位の小さな差は出ますが、長いログ出力や描画による延長を抑えます。

「会話ログ」では、実際のE84の認識結果とAIの返答を時刻付きで表示し、過去の会話を選択・JSONで書き出せます。直近20会話、各200発話までをこのMacの `calibration_ui/.runtime/conversations.json` に保存します（Git対象外、ファイル権限0600）。録音は保存しません。保存開始前の会話は、残っていた実機ログの範囲だけを引き継いでいます。

Web画面はMacのUSBを介して操作します。Mac上でサーバーを起動している間だけ利用でき、保存後の自動通話にMacは不要です。USBプロトコルは改行区切りの `@get`、`@begin`、`@set c|e r|p <角度>`、`@time d|c|e|r <ミリ秒>`（通話前待機・通話押下・終了押下・復帰）、`@save`、`@cancel`、`@test c|e`、`@stop`、`@mirror e`（終了の両角度を無動作で反転）、`@angles c|e <待機角度> <押下角度>`（編集中の角度を無動作で復元）です。後者2つも調整モードかつ停止中だけ受け付けます。`[CAL]` に続くJSONが実際の保存・編集中の角度と `test_busy` / `test_target` を返します。単体検証は `python3 -m unittest discover -s calibration_ui -p 'test_*.py' -v` で行えます。

### USBだけでサーボを確認する

115200 baudのUSBシリアルから、次の1文字を送ります。Enterは不要です。Wi-Fi・E84・APIへの接続は不要で、通話や音声再生を開始しません。

| コマンド | 動作 |
| --- | --- |
| `1` | 通話用サーボ（標準GPIO26）を1回、押下位置→待機位置へ動かす |
| `2` | 終了用サーボ（標準GPIO17）を1回、押下位置→待機位置へ動かす |
| `x` | 実行中の単体テストを待機位置へ戻して終了する |
| `s` | 状態を表示する |

各動作は通常のサーボ設定に従い、標準では通話前に3秒待ち、押下300ms・復帰1000msでPWMを停止します。終了ボタンには事前待機を入れません。ネットワーク接続中や別のサーボ動作中は開始を拒否し、単体テスト中は新規TCP接続を受け付けません。`x`は単体テスト専用で、通話中の終了操作には使いません。起動時やコマンド未入力時に自動で動かしません。

初回は腕が自由に動く状態で1台ずつ確認します。完了ログはPWM操作の完了を表し、実際に回転したかは目視で確認してください。

### E84からの音声・通話制御

E84がTCPに接続し、ペアリングトークンで認証してから通話を開始します。音声はPCM16LE、16kHz、モノラル、最大20ms/640バイトのフレームです。詳細は [共通プロトコル](../PSOC_Edge_E84/docs/voice-stream-protocol.md) を参照してください。

- 64フレーム（最大1.28秒、約40KiB）を上限に保持し、満杯ならTCP読み込みを止めます。受信してキューに入った音声だけをACKします。
- 10フレーム（通常200ms）を蓄えてからスピーカーへ渡します。短い返答は `OUTPUT_END` 到着時に再生します。
- `OUTPUT_END` が届き、全PCMの再生要求が終了し、48kHz/8×256サンプルのDAC出力に対して60msの排出待ちを終えて初めて `PLAYBACK_DONE` を返します。音声生成の終了、無音、受信中断だけでは完了扱いにしません。
- 音量は255/255、Wi-Fi省電力は無効です。32フレーム（640ms）を先読みし、48フレームまで先行する累積ACKで転送量を制御します。APIの未確認10フレームを加えても64フレームのリングを埋めません。短い音声はOUTPUT_END後に再生し、受信確認と実再生完了は別々に扱います。
- PCMバッファは非同期スピーカータスクが参照し終えるまで再利用しません。音声中は画面描画を控えます。
- 最大3000フレーム（20msフレームなら60秒）の返答を受け付けます。音声受信が15秒止まった場合、途中パケット/返信送信/再生が5秒進まない場合、接続が180秒無活動の場合はエラーとして切断します。
- 切断・キャンセル時はスピーカータスクとI2Sを停止してからバッファを解放します。E84は再生完了通知がない限り次の録音へ進めません。

## サーボ配線のサンプル設定

サーボ2台で別々のボタンを押す初期設定です。通話操作または明示的な単体テストまでPWMを出さないので、起動だけでサーボは動きません。

| 対象 | M5Stack Basic側 |
| --- | --- |
| 通話ボタン用サーボの信号 | GPIO26 |
| 終了ボタン用サーボの信号 | GPIO17 |
| サーボGND | 外部電源GNDとM5のGNDを共通接続 |
| サーボ電源 | サーボ仕様に適した外部5V電源 |

GPIO25は内蔵スピーカーが使うため割り当てません。[M5公式Basicピン配置](https://m5stack.oss-cn-shenzhen.aliyuncs.com/resource/docs/static/pdf/static/en/core/BASIC%20v2.6.pdf)で、GPIO26とGPIO17の端子位置を確認できます。ここでのGPIO17割り当ては **Basic** 向けです。Fireなどの別機種へそのまま適用しないでください。

`servo_config.example.h` は初期設定です。50Hzで動作し、標準では通話前3秒待機→押下位置を300ms保持→待機位置へ1000ms戻してPWMを停止します。角度と時間はWeb UIの保存値が優先します。取り付け方向に合わせ、通話用G26は `M5_SERVO_CALL_REVERSED 1`、終了用G17は `M5_SERVO_END_REVERSED 0` と逆向きにしています。これらのマクロは初期値だけに適用され、保存済み角度を変更しません。既存の終了側を反転する場合はWeb UIの反転操作を使います。

| 設定 | 待機→押下→待機の指示値 | PWMパルス幅 |
| --- | --- | --- |
| G26・反転 | 180°→0°→180° | 2000→1000→2000µs |
| G17・通話側と逆向き | 0°→30°→0° | 1000→約1166→1000µs |

初期の押下角度は `M5_SERVO_CALL_PRESS_DEG 180`（G26、反転後0°）と `M5_SERVO_END_PRESS_DEG 30`（G17、反転なし）です。実機に合わせた調整・保存値が優先されます。`M5_SERVO_PRESS_DEG` は個別設定がない旧設定ファイル向けの共通値です。

USBの `1` / `2` と、E84経由の通話開始・終了操作は、同じ `attachAndPressServo()` / `neutralServo()` と上記設定を使います。APIから角度や保持時間を指定する処理はありません。最後の音声をM5が再生し終えると、APIの `call_end` をE84がM5へ中継し、G17をこの確定値で押下・復帰させます。キャンセルや切断時の終了操作も同じ設定です。起動ログまたはUSBの `s` で、実際に書き込まれた設定を `[SERVO] Settings` として確認できます。

反転は `180 - 角度` へ変換するため、待機位置も変わります。初回操作前は旧位置に止まっていることがあり、初回の動きだけでは反転後の方向を判断できません。角度は1000〜2000µsを0〜180°へ割り当てた指示値であり、実際の回転角はサーボによって異なります。ホーンを外した状態で待機位置を確認してから、ボタンへの当たり方に合わせて調整してください。

設定を変えるときは、次のファイルを作って編集し、再ビルドします。

```sh
cd /Users/fukawanozomi/Documents/ChatGPT/jphacks/M5Stack_Basic_E84_Link
cp servo_config.example.h servo_config.h
```

`M5_SERVO_CALL_PIN` / `M5_SERVO_END_PIN`、各サーボの `M5_SERVO_CALL_REVERSED` / `M5_SERVO_END_REVERSED`（0または1）、初期角度、パルス範囲、初期押下・復帰時間を変更できます。使える信号GPIOは16/17/26です。同一ピンを両方へ指定すれば、同じボタンを押すサーボ1台にもできます。その場合は反転設定も両方揃えてください。`servo_config.h` はGit対象外です。古い独自設定に反転項目がない場合は、互換性のため両方0として扱います。

サーボを接続する前に通話・音声だけを試す場合は、`servo_config.h` を **`M5_SERVO_ENABLED 0`、`M5_SERVO_MANUAL_TEST 1`** にします。通話ボタンを人が押してからM5のAを押すと開始完了、終了ボタンを人が押してからM5のCを押すと終了完了を返します。確認を60秒以内に行わなければ中断します。両方0では `servo_disabled` エラーを返し、押していないボタンを完了扱いにはしません。

同じ通話内の操作再送ではサーボを重ねて動かしません。切断後に同じ通話IDで再接続する要求も直近64件について拒否します（RAM記録なので再起動で消えます。E84は通話IDを再利用しません）。実サーボモードで通話押下後に通信が切れた場合は、音声を停止し、サーボを待機位置へ戻してから終了ボタンを一度押します。これはPWM動作完了の確認で、実際にインターフォンが通話状態になったかを検出するセンサーはありません。

接続が生きている状態で `CANCEL` が届いた場合は、音声を停止してから終了ボタンを操作し、`CALL_ENDED` を返すまでTCPを保持します。通話ボタンをまだ操作していない場合はサーボを動かさず完了を返します。押下途中なら待機位置へ戻してから終了操作へ移ります。手動テスト中のキャンセルは、終了ボタンを人が押してM5のCで確認する必要があります。

## 検証

```sh
bash tests/run.sh
node tests/ui_test.mjs
bash run.sh build
```

ホストテストは旧UDPとの互換性、破損/重複PCM、音声の順序、キュー満杯時の受信停止、短い音声、終了通知と30ms待ち、サーボ再送、切断時停止を検証します。ASan/UBSanを有効にしています。音量・残響・実サーボの角度・実機連続通話は配線後に確認してください。

## ファイル

- `M5Stack_Basic_E84_Link.ino`：Wi-Fi接続・再接続、UDP待ち受け、画面表示。
- `link_protocol.cpp` / `link_protocol.h`：受信データの検証、トークン照合、重複排除、pong生成。
- `stream_protocol.cpp` / `stream_protocol.h`：DVS1フレーム、通話状態、PCMキュー、通話ID重複防止。
- `stream_receiver.cpp` / `stream_receiver.h`：TCP受信、スピーカー再生、完了通知、サーボ動作。
- `servo_pwm.cpp` / `servo_pwm.h`：ゼロ出力からの開始、専用タイマー、PWM停止と信号LOW固定。
- `servo_config.example.h`：GPIO26/17のサンプル配線、サーボ設定、手動テストモード。
- `link_config.h`：ローカル専用のSSID・パスワード・ポート・トークン。E84の設定スクリプトから生成します。
- `run.sh`：M5Core向けビルド・書き込み。

UDP/TCPの共有トークンは平文で送信するため、信頼できるLANで使用します。資格情報を含む設定ファイルやビルド済みファームウェアは共有しないでください。

「音声用TCPを確認」はE84の `v` 診断を実行し、音声通話と同じ8769/TCPのHELLO/READY認証とPING/PONGを確認します。通話・終了ボタン、マイク録音、音声出力、agentは起動しません。角度調整中はM5が新規TCP接続を拒否するため、保存または取消後に実施してください。UDPの成功だけでは音声用TCPの成功は確認できません。

通信エラーで通話終了を確認できない場合、新しい通話・録音は停止状態を維持します。修正版E84では通信リソースを解放して診断ボタンを再び利用可能にし、画面に復旧待ちを表示します。通話の再開には実機の状態を確認して両ボードを再起動してください。
