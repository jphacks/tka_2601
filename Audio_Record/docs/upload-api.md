# 呼び出し録音の保存API案 v1

この契約は今回の試作向けの提案です。既存の公開Door APIに実装済みという意味ではありません。
`tools/receiver.py` はこの契約のローカル参考実装です。

## リクエスト

`PUT /v1/doorbell/recordings/{event_id}`

- TLSで保護されたHTTPS/443を使用。
- `event_id`: ハードウェア由来のエントロピーから生成した128bitのID。小文字の16進数32文字。
- `Authorization: Bearer <device-token>`: 認証とデバイスの所有者判定に使用。
- `Content-Type: audio/wav`
- `Content-Length`: 44〜192044バイトの範囲。データは1サンプル以上。
- `X-Audio-Match-Score`: DTW距離。小さいほど類似。手動録音は -1。
- `X-Audio-Model-Version`: 特徴の形式バージョン。現在1。
- 本文: 44バイトの標準PCM WAVヘッダー + 16kHz/16bit/mono/little-endianのPCM。

ボードはフラッシュから小分けに読み出して送信します。WAV全体を追加のRAMバッファに展開しません。
再送時も同じIDとPCMを使います。受信側はIDを所有デバイスに関連付け、他の所有者の録音を書き換えられないようにしてください。

## 応答と保存確認

新規に永続保存できた場合は `201 Created`。
同じID・同じ音声が既に保存済みの場合は `200 OK`。
どちらも本文は `{event_id}\n` のみ（`text/plain`）とします。

ボードはHTTPステータスだけでなく、応答本文のIDが送信対象と一致するかを確認します。
保存前にACKを返さないでください。アップロード途中やサーバーの保存失敗では成功を返しません。
同じIDで異なる音声が届いた場合は `409 Conflict` とし、保存済みデータを維持します。

- 401/403: 認証・権限エラー
- 400: WAV不正または途中で終了したアップロード
- 413: サイズ超過
- 415: 形式不正
- 503: 保存処理失敗

ボードは成功を確認できない場合、元の録音とIDを保持して再試行します。
サーバーは受信時刻を記録します。この初版は呼び出し開始のUTC時刻や通知イベントを別送していません。

## 今後の統合

検知時に小さなイベントを先に送るAPI、iPhone通知、AI会話の開始は別途接続します。
既存サーバーが別のAPI形式を要求する場合は、その契約に合わせてボードの送信側を変更します。
ローカル参考実装はファイル保存のみで、音声認識・LLM・通知を起動しません。
